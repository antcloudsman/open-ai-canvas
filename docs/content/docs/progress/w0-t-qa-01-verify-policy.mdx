| bun 1.3.9 旁路 | 对齐失败时书面偏差 | 旁路 `bun-1.3.9-pin\...\bun.exe` = **1.3.9**；**未**替换全局 PATH |

### bun 偏差原因（书面）

1. `bun upgrade` 无钉版本开关。
2. 官方 install.ps1 装到最新 1.4.4。
3. 全局 bun 多仓共用，强降级有风险。
4. **结论**：发版/CI 以 quality.yml **1.3.9** 为准；本机日常可用 1.4.4，需对齐时用旁路二进制。

### 后端 verify 不再因「找不到 go」失败

装好 Go 1.25.6 后，`verify-before-push.mjs` 中 `spawnSync("go", ["version"])` 可通过；`--only backend` 不再因无 go 而 `process.exit(1)`。

## 2. 空跑策略（不得冒充全绿）

- 相对 `origin/main` 0 改动且未 `--only`/`--all` 时 tasks 为空，原逻辑打印「没有需要运行的检查。」后 exit 0。
- **强制口径**：0 改动空跑 / 「没有需要运行的检查」= **非全绿**，禁止宣称全量门禁通过。
- **本 PR**（`scripts/verify-before-push.mjs`）：无任务早退的 stdout 显式 **【非全绿 / 空跑】**，说明不得宣称全量门禁通过，并打印 skipped / notCovered；exit code 仍为 0。成功收尾若存在 skipped 或 notCovered，追加「非 CI 全量等价」提醒。
- 全量门禁：CI `quality.yml`，或本机 `--all` / `--only` 实跑完成。
- 未延长 `TASK_TIMEOUT_MS`，未拆分 `web:test`。
