## 2. 成功回滚

备份之后、回滚之前，在运行中的栈上做了破坏：

- `/data/handtest-dirty.txt` 内容 `dirty-after-backup`
- `UPDATE handtest_marker SET note='mutated-after-backup' WHERE id=1`
- `INSERT` id=2，`dirty-after-backup`

然后由已安装的更新器执行：

```bash
curl --unix-socket /tmp/oac-handtest-updater.sock \
  -H "Authorization: Bearer <redacted>" \
  -H 'Content-Type: application/json' \
  -d '{"reason":"handtest success rollback"}' \
  http://localhost/v1/rollback
```

接受时 `phase=rolling_back`。轮询到 `FINAL rolled_back`。日志：


id=2 和被改过的 note 都回到了这份 ZIP。没有 `.hostupdate-restore-new` 或 `.hostupdate-restore-old`。

## 3. 半恢复

成功回滚后向 `/data/bulk.bin` 写入 200MiB，再打第二份备份 `backup-20261104-172159`（316916391 字节，`sha256:514cadb72ef0801f8652969175ee958befcf1e72b1f0ae1e06b07bedbe3dab95`），把栈重新拉起，然后再次 `POST /v1/rollback`。

解包一开始，数据卷 `/var/lib/docker/volumes/open-ai-canvas-handtest_backend-data/_data` 出现 `.hostupdate-restore-new`。当时立刻 `docker kill` 一次性恢复容器 `open-ai-canvas-handtest-backend-run-e4e294cea1db`。

## 4. 恢复前 yingce-agent 已停止

两轮回滚的日志都先写「停止 Web、Backend 与 Agent」，下一条才是「恢复后端数据目录」。半恢复在标记目录已经出现时，`yingce-agent` 不在 `docker compose ps` 里，直到用例结束也没有被拉起。它没有挂载 `/data`，backend 同样处于停止，因此这段时间没有 Agent 写入口。

`docker events --format '{{.Status}}'` 在 Docker 29.1.3 上模板报错（`can't evaluate field Status`），事件流没有记下来。停服顺序以上面的更新器日志时间戳和标记出现时的 `ps` 为准。
